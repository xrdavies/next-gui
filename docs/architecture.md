# 架构

## 一句话

**声明式 UI 描述界面；retained 树长期持有节点并做脏区更新；GPU 与软渲染是同一场景图的两种后端；Immediate 是显式嵌套的可选视口。**

## 语言选型

### 实现语言：Rust

- **选定：Rust** 作为运行时与工具链的实现语言。
- 理由概要：弱机可控、无 GC 停顿、易嵌 C ABI 给工控侧；办公室桌面同样可跑。
- **C++**：不作为默认实现语言；仅在需要对接既有工控 / 遗留库时，经 **可选 FFI** 暴露，细节可回头再抠。

### 声明式 UI 层：自研 DSL + Rust API

| 写法 | 角色 |
|------|------|
| **自研 DSL**（类似 `.slint` / QML） | **主声明式语言**，面向配屏、HMI、热重载与静态检查 |
| **Rust 宏 / API** | 代码侧等价物：复杂逻辑、自定义控件、与业务库直连 |

二者编译 / 绑定到**同一套** `scene` / `ui` 语义（retained 运行时），不是两套控件模型。

**明确不做**：不以 JS/TS 为默认声明层（会把产品往 Web 运行时牵）；若以后要脚本扩展，再单独加沙盒，不当内核。

## 模块与边界

模块划分大体如下，细节可回头再抠；当前按 crate / 包边界理解即可。

| 模块 | 职责 | 不越界 |
|------|------|--------|
| `platform` | 窗口、输入、时钟、剪贴板薄封装 | 不含控件、布局 |
| `scene` | retained 节点树、脏区、命中 / 焦点 | 不含具体绘制 API |
| `layout` | 盒模型 / 约束布局 | 不碰 GPU |
| `render` | 场景图 → 绘制命令 | 只暴露后端接口，不含具体后端实现 |
| `render-soft` | CPU 软渲染后端 | 不持有业务控件语义 |
| `render-gpu` | GPU 后端 | 不持有业务控件语义 |
| `text` | 字体、shaping、换行（含 CJK） | 经 `render` 出字形，不直连业务控件 |
| `ui` | 声明式 DSL / API、组件、绑定 | 只操作 `scene`，不直连渲染后端 |
| `immediate` | 可选 Immediate 视口 | 嵌在 `scene` 节点内，不当整栈默认 |
| `profile` | Field / Office 特性与性能预算 | 配置层，不是第三套 UI |

### 依赖方向

```text
ui  →  scene / layout  →  render  →  render-soft | render-gpu
                ↑
           platform（垫底：窗口 / 输入 / 时钟）

immediate ──旁路挂到──→ scene（显式视口节点）
profile 配置各层能力开关与预算，不形成第二条 UI 栈
```

- `ui` 只通过 `scene`（及布局结果）驱动界面，不绕过抽象去调 GPU。
- `layout` 纯几何，不感知后端。
- `render-*` 只消费绘制命令，不理解按钮 / 列表等控件语义。
- `platform` 不包含控件与布局。

## 分层（产品视角）

```text
应用（现场 HMI / 办公规划 · 设计软件）
              │
    自研声明式 UI + 组件库（DSL + Rust API）
              │
    retained 场景图 / 布局 / 事件 / 焦点·命中
              │
       ┌──────┴──────┐
       │             │
   GPU 后端      软渲染后端      ← 同一场景图
       │             │
  平台窗口 / 输入 / 显卡或 CPU
              │
  Optional: Immediate 子树（局部或整窗，显式声明）
```

| 层 | 职责 | 自研边界 |
|----|------|----------|
| 应用 | 现场 HMI、办公工具 | 产品代码 |
| 声明式 + 组件 | DSL/API、绑定、样式、控件 | **必须自研**（见上文语言选型） |
| retained 运行时 | 节点树、布局、脏区、动画时钟、命中测试 | **必须自研**（`scene` / `layout`） |
| 渲染抽象 | 场景图 → 绘制命令 | **必须自研**（`render`） |
| GPU / 软渲染后端 | 合批上 GPU，或 CPU tile/扫描线 | **必须自研**；对接系统 Vulkan/GL/Metal 等 |
| 平台 | 窗口、输入 | 系统 API 薄封装（非第三方 UI 框架） |
| Immediate 视口 | 每帧代码描述的子区域 | 可选插件；显式开启 |
| Profile | Field / Office 档位 | 配置，非第二套框架 |

「不拼凑框架」= 不以现成 UI 运行时为产品内核。窗口/GPU 驱动接口与（阶段性）字体 shaping 基础设施不在此禁令内。

## 声明式 + retained + GPU + Immediate

```text
开发者写法          运行时                 绘制
─────────          ──────                 ────
声明式 DSL/API  →  retained 节点树    →  GPU 后端（能用则用）
                   脏区失效 / 局部更新     软渲染后端（弱机兜底）
                          │
                          ├── 默认可走整棵 retained
                          └── 某节点标成 Immediate 视口时：
                              仅该区域每帧重建描述再合入绘制
```

- **主路径**：声明式 + retained。状态变 → 局部更新树 → 脏区重绘。
- **GPU**：加速「怎么画」，不是换掉树模型；Office 优先，Field 可关或降级。
- **软渲染**：与 GPU 共用场景图，保证无独显 / 弱核显可运行。
- **Immediate**：整窗或局部均可；工业双场景下推荐**主体 retained + 局部 Immediate**。需划清输入焦点、裁剪与刷新边界。

### Immediate 嵌入方式

- **局部**：retained 树中显式区域（概念上 `immediate { ... }`），仅该视口按每帧描述重建。
- **整窗**：允许，适合工具 / 诊断窗；**不作为 Field 主 HMI 默认**。

## Field vs Office

| | Field（现场） | Office（办公） |
|--|---------------|----------------|
| 树模型 | retained（同一套） | retained（同一套） |
| 渲染 | 软渲染优先；核显可选 | GPU 优先 |
| 刷新 | 脏区 + 停帧 / 降 fps | 更高帧率与动效预算 |
| 特效 | 少动画、少模糊/重阴影 | 更丰富动效、图表、多窗口 |
| Immediate | 默认关（或仅调试） | 局部工具面板可选 |
| 视觉原则 | 高对比、清晰、稳 | 在同一设计系统上更丰富 |

一套场景图，两套 **Backend + Profile**，不是两套 UI。

## 明确不做

- 不以 Immediate + 满血 GPU 为整栈默认
- 不以运行时「整窗 Immediate 自动翻成 retained」为产品主叙事（内部缓存/diff 可以是实现细节）
- Field 不以 Web 壳（Electron 等）为 UI 内核
- 不以 Slint / Qt Quick / Flutter / ImGui 等现成框架为产品底座
- 不以 JS/TS 为默认声明式 UI 语言
