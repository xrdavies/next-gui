## Primary scope and reference

Execute SQL now places independently resizable,collapsible,read-only messages below
its result grid. Outcomes include completion/error,completed statement count,last
statement,elapsed time,returned rows and affected rows. DML RETURNING reports both
counts. Each statement still runs once on the existing owning connection; results
continue to use the complete typed snapshot. Earlier pending changes remain pending
when a later statement fails. Last-statement feedback follows upstream's replacement
behavior; this is not a new statement-history viewer.

A statement's previous `sqlite3_changes` value must not appear as a later DDL count.
The existing parser classifies normal DML,including WITH;SQLite remains responsible
for execution. Unknown newer grammar falls back to observed changes for feedback only;
an unknown zero-change statement can omit an affected-row count. Trigger side effects
are excluded from the reported direct DML count. SQLCipher message details are redacted.

Message selection/scroll belongs to the SQL tab. The visible flag and preferred split
ratio round-trip through JSON and XML extensions. New execution starts at the outcome
header; subsequent rebuilds,copy selections and tab switches retain the user's view.
No next-gui framework change was necessary for this batch.
