## Findings

### R-20261029-44c453d1409d-F01

**Default-application feedback can outlive its request**

- Status: in_progress
- Severity: P3
- Owner: codex
- Platform: shared / all
- Location: cell_actions.rs::poll_desktop_opens and main.rs::open_url
- Introduced by: `44c453d1409d`

The initial status says Opening, while successful polls consume the request
without changing that status. Also, a late error for an already canceled external
copy still sets a global error even when its path no longer matches an active
session. Source/path matching prevents canceling a newer external session, so
this is feedback noise rather than a wrong-cell write. This is a code-path
finding; successful default-app runtime was not accepted.

Use request wording that does not promise ongoing progress, and ignore external
completion/errors after that exact copy is closed. Add a targeted regression
through the application's pending-request path and verify the current session
and status survive. Include this in the next source/QA cycle before publication.

Implementation follow-up: request text now says `Open requested`, and the poller
ignores errors for closed external-copy paths. The targeted Unix regression
drives asynchronous NUL-path spawn failures (no application launched) through
the pending queue: stale copy preserves the newer copy/status, matching copy
closes and reports the error, ordinary requests still report errors. Targeted
test passed; full checks and verification will accompany the row-key cycle.
