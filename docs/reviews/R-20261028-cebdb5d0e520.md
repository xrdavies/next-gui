## Implementation and safety boundary

Table/view and immutable query snapshots stream through the same buffered writer
on a worker owning the existing live connection. Spawn failure returns the
connection; ordinary failure/cancel returns it with pending changes intact.
Progress records prepared files and emitted rows without an expensive counting
query. UI polling only joins finished jobs; resizing and modal controls keep
responding. The shared guard now covers CSV and exports; browse add/close/switch
also use it. Escape, title close or native CloseRequested requests cancellation
and retains the window until work returns. A panic reports lost connection and
clears stale cached row identities; OS crashes are not claimed recoverable.

Cancellation is cooperative before/after a row or write, without SQLite interrupt
(which can roll back pending edits). An atomic phase transition separates cancel
from final publication: a successful cancel leaves all destination files intact;
once publication begins Cancel is disabled and status says Finishing. Each file
still replaces atomically. A filesystem failure during multi-file publication
can leave earlier files completed and reports their count. A single slow SQLite
function/read/write cannot be forcibly aborted; UI explains waiting for it.
