What this change does: Shared TextArea can position the caret with the pointer,
select text, scroll long scripts, replace selections and undo edits. SQLite's SQL
and Find pages use that capability, retaining an editing session per SQL tab and
executing selected SQL when present. No dependency or database/project format changed.

Expected load: one local desktop user with ordinary multi-line SQL scripts. This
is not a large-file editor acceptance claim. Glyph layout is linear in document
size; raster masks and selection nodes are limited to the visible viewport.

- NG-03 basic editing is implemented in next-gui; e28 has no private caret or
  byte-offset find engine. It uses shared APIs and an opaque session per SQL tab.
- UTF-8 remains intact because public positions use Unicode scalar indices.
  IME preview/commit replaces selection and matches the drawn candidate position.
- Find displays the same script in its panel. Find Next selects/reveals a match;
  Replace changes that selection; Replace All is one undoable operation.
- Execute and Cmd/Ctrl+Enter use selected SQL or the entire script; shortcuts
  continue to work with the SQL toolbar hidden. Cmd/Ctrl+F opens Find.
- Copy returns selected text only; cut removes it only after clipboard write succeeds.
- Restore rejects different document content; project loading clears editing sessions.
  Rebuild, tab switch and Find resize preserve/reveal the caret as applicable.
- e21 maps the new keys and has a `textarea` QA mode without an occluding Drawer.
- Shared scene/render commands are reused. Selection uses alpha-mask coverage,
  because plain FillRect ignores alpha. Caret coordinates use integer pixels.

No new unresolved must-fix finding was found in this editing change after the
integration and rendering fixes below. This does not clear the earlier application findings.

## Limits and handoff

- Editing sessions are in memory; history is not serialized into projects.
- Undo/redo each retain up to 100 snapshots / 8 MiB, except one oversized edit.
  Immutable snapshot text is shared between copied sessions.
- Syntax/completion/line numbers, grapheme/word navigation, drag-scrollbar,
  horizontal scroll, regex/options and large-document profiling remain unimplemented.
- DDL/CSV receive shared editing behavior but do not yet preserve sessions through
  application rebuilds. The SQL Comment action still uses the prior whole-document
  transform and is not connected to editor undo/selection. These are not included
  in the F01/F04 verified subset.

Verdict: the shared editing slice is ready for integration. Full SQLite Browser
parity remains incomplete; fix the remaining P1 cases before treating it as a
replacement database client.
Not checked: native desktop input/clipboard/IME, other OS runtimes, full-window
Soft/GPU pixel acceptance, huge scripts and advanced code-editor behavior.
