## Implementation and reference

`wizard_col_sources` records original editable-column identity separately from its draft name. UI list mutations carry that identity; new columns use None. The DB helper validates source mappings/order/definitions and performs original→unique temporary→target renames, DROP/ADD and table rename in one existing savepoint. SQLite owns rewriting dependent SQL. The legacy helper retains its old ambiguous add/drop protection for callers without an explicit mapping.

Application options rename named identities in a single pass, so a/b swaps never map twice. Raw SQL WHERE text is intentionally left for the user to edit; structured filters follow their columns. Saved DDL and subsequent query failures have separate outcomes.

Upstream reference remains DB4S v3.13.1 EditTableDialog. SQLite documents dependency rewriting and rejection of ambiguous trigger/view references in [ALTER TABLE](https://www.sqlite.org/lang_altertable.html); its [trigger documentation](https://www.sqlite.org/lang_createtrigger.html) explains schema qualification for temporary triggers. The additional temp-trigger failure below is observed against the locked SQLite3.45.3 engine, rather than inferred from current documentation.
