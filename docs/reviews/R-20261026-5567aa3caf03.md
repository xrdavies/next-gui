What this change does: Image now renders its actual RGBA pixels through the shared
Scene, Soft and GPU layers. SQLite's image dock keeps the decoded PNG/JPEG source
resolution and fits it without distorting its aspect ratio, replacing the former
160px reduction and 24-cell mosaic.

Expected load: one local database user viewing a static image. This is not image
editing, animation, huge-image or sustained high-frequency redraw acceptance.

## Scope and review

Read the scene encoding/dirty/clip contract, both renderers and their mask callers,
Image builder/painting/accessibility/DSL exception, e26 catalog caller, e28 cell
selection/mode switching/decoder/UI rebuild/QA paths, tests and applicable findings.
No pending `fixed` findings existed. Existing nine unpublished commits were
preserved. Feature-branch fetch initially failed with HTTP/2 framing; HTTP/1.1
retry succeeded and confirmed the remote branch remained an ancestor. The user's
explicit feature-branch product work takes precedence over the routine main-only
handoff workflow.

- RGBA resources validate nonzero dimensions, exact length and arithmetic overflow.
  Their immutable Arc is shared into scene commands without pixel copies.
- Destination geometry stays intact when clipped; texture coordinates therefore do
  not stretch the visible piece. Both backends clip at pixel centers, including
  fractional boundaries, and use straight-alpha source-over compositing.
- GPU reuses the existing blit vertex/layout/sampler/upload code. Images exceeding
  the adapter's texture dimension are tiled; mask drawing retains its old shader.
- Image needs two auxiliary nodes (image and caption), preserves aspect ratio and
  clips caption text. Public builder signatures remain unchanged. `mosaic_max`
  remains a compatibility field and is ignored. Incomplete pixel buffers now
  produce empty image content instead of padding/allocating the declared size.
- e28 checks dimensions before pixel decoding (maximum 16 × 1024 × 1024 pixels),
  passes a 128 MiB allocation budget to the decoder and reports decode failures.
  Original BLOB bytes are untouched; redundant decode calls were removed.
- No dependency or database/project format changed. `RgbaImage`, `Node::image` and
  `DrawCommand::BlitRgba` are public additions; external exhaustive enum matches or
  struct literals must add the new field/variant. All workspace consumers compile.

No new unresolved must-fix finding was found in this change. It does not resolve
the earlier cell-draft/type, SQL-draft or general layout findings.
