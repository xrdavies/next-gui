## Scope and macOS parity

Original v3.13.1 [SqlTextEdit::toggleBlockComment](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqltextedit.cpp) uses current line or selected lines, excludes an endpoint at the next line's start, chooses mode from the first line and groups changes in one undo action. Uncomment removes exactly two leading hyphens after spaces/tabs and at most one following space. e28 follows this behavior with LF/CRLF-preserving Unicode scalar ranges.

The old AppState whole-tab mutation was removed. Toolbar and editor-focused Ctrl/Cmd+/ call the same Demo action. It focuses the editor and snapshots the post-edit session, so rebuild/tab/file draft machinery preserves undo. Tooltip and accessible name describe the command; no OS accessibility bridge claim. No persistence format/dependency/platform-specific branch was added.

`Ui::replace_text_area_range(id, range, text)` validates scalar offsets and read-only state, records the original selection before replacing the supplied range, clears stale highlights/preedit and reveals the resulting caret. Existing selection replacement delegates to it; search/replace now uses it directly instead of changing selection before recording history. No text paint code changed. Source/comment-only final amendment followed the completed checks.

Initial new UI test incorrectly expected an empty-history Undo key to return false; existing contract consumes it. Corrected the assertion to verify unchanged document, then re-ran the targeted and full suites. This is test correction, not a product regression. ## Findings

### R-20261027-3ab164fed903-F01

**Commenting a selection modified unrelated SQL and lost editor history**

- Status: verified
- Severity: P1
- Owner: grok
- Platform: e28 / shared
- Location: former `AppState::toggle_sql_line_comment`, toolbar handler
- Introduced by: pre-existing whole-tab implementation; exact commit not isolated.

Baseline selected only the second line of a three-line Chinese CRLF script. Actual old result commented all lines, changed line endings and added a final newline. It also stripped every leading hyphen when uncommenting (`---1` became `1` instead of `-1`) and bypassed TextArea undo history. Users could change unselected statements or the sign of a value without an undo step.

- Fix/verification: `3ab164fed903d2415b6ff9f354a8361f6c0577ff`.
- The same failing selection baseline now passes, including original selection restoration on undo and redo after rebuild. All 316 tests and strict checks pass.
- Native gesture/original-binary acceptance remains unrun. CR-only line documents still follow TextArea's current LF-based layout, explicitly marked `shortcut:`; full line-ending support remains open.
