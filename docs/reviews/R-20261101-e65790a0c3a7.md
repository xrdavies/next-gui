## Findings

### R-20261101-e65790a0c3a7-F01

**Right-click inside a range uses the old active cell; independent active cells shrink clipboard ranges**

- Status: open
- Severity: P1
- Owner: codex
- Platform: all
- Location: `browse_menu::open_browse_cell_menu`, `Demo::poll_selection_changes`, `state::copy_browse_cells`, `cut_browse_cells`, `paste_browse_cells`
- Introduced by: `f48b404` context routing; latent active/end-point conflation predates it

Qt sets the clicked current index without replacing an already selected rectangle.
DB4S context actions then use that current index. This target leaves the old active
index unchanged when clicking inside a selected range: filter and format actions
can therefore target the wrong value/column. Simply updating the active index is
insufficient: polling and clipboard methods derive range ends from the active
index, shrinking copy/cut/paste/NULL scope and invalidating the intended rectangle.
The context target also omits the independent range endpoints from stale guards.

A regression selects rows 0..2, columns 0..1, then right-clicks (0,0):

```text
context actions must use the clicked cell
left: (Some(2), Some(1))
right: (Some(0), Some(0))
0 passed; 1 failed
```

Pre-fix log: `/tmp/next-gui-context-active-before.log`. Preserve the clicked active
cell independently from both oriented selection endpoints; copy/cut/paste must
consume those endpoints, and context identities must include them. Verify both
selection directions, scoped formats, typed copy/paste, NULL/Cut and later-row
constraint failure without partial writes. Candidate repair is being tested.
