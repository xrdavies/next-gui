## Findings

### R-20261027-2bfc8ad51380-F01

**Project loading suppresses errors from its restored browse query**

- Status: open
- Severity: P2
- Owner: codex
- Platform: e28 / shared
- Location: `examples/28_db_browser/src/state.rs::open_project`
- Introduced by: pre-existing `_ = refresh_browse()`; new filter operators make more cases visible

Code-based evidence: after applying the project's browse settings, `open_project`
discards `refresh_browse()`'s error and returns success with “Project opened”. A
stored invalid WHERE or REGEXP can therefore show no rows without exposing the
query error. No runtime reproduction is claimed in this review yet.

Preflight restored queries before replacing a usable session, and ensure any
remaining refresh failure is reported. Add invalid WHERE/REGEXP regressions,
including an empty table and preservation of the previous session.

#### Resolution checkpoint (2026-10-27)

The new `invalid_project_browse_queries_preserve_current_session` regression first
failed on malformed `id =`: `open_project` returned success. The implementation
now preflights all restored browse tabs, including legacy JSON fallback state,
before adopting the candidate connection. It validates slash-delimited patterns
independently of row count and executes the normal bounded preview to detect
runtime match errors. The final refresh also propagates errors. Column discovery
and PCRE2 compilation reuse shared helpers used by refresh/export/XML paths.

`cargo test --offline --locked -p e28_db_browser`: 74 passed; strict package clippy
passed. Regressions cover malformed WHERE, injected second statements, column and
global patterns, empty-table XML patterns, inactive tabs, bounded-match failure,
legacy JSON and preservation of the prior connection/SQL tabs. Logs:
`/tmp/next-gui-project-preflight-{before,tests,clippy}.log`.
