## macOS parity

The linked SQLite catalog, not CREATE-string prefix matching, identifies virtual
and shadow tables. SQL selection treats each virtual root and its internal tables
as one unit; ordinary tables with similar name prefixes remain independent.
CREATE generates shadow structure; staging exports exact physical shadow values,
including contentless indexes, and restores them only in fresh/explicitly replaced
roots. No writable_schema directive or connection security change is introduced.

A savepoint flushes pending virtual-module index buffers before snapshot reading.
The existing savepoint helper retains prior transactions and rolls back staging
failures. The complete staged file leaves the savepoint successfully before the
existing cancellation/publication boundary atomically replaces the destination.

This matters because [contentless FTS5](https://www.sqlite.org/fts5.html#contentless_tables)
returns NULL for visible columns: copying those values cannot preserve its search
index. [SQLite table_list](https://www.sqlite.org/pragma.html#pragma_table_list)
provides virtual/shadow classifications. Actual linked SQLite round trips above
verify the approach; original-binary compatibility remains untested.
