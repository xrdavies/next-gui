## Findings

### R-20261027-8ab0778f3a16-F01

**Failed table/view switch replaces the current browse state and hides the error**

- Status: verified
- Severity: P1
- Owner: codex
- Platform: e28 / all
- Introduced by: pre-existing selector path before this review
- Location: `Demo::apply_browse_select`, `poll_selection_changes`

The selector mutated table/title, reset the result and navigation state, then
ignored refresh_browse's error. An unqueryable view therefore replaced the working
browse context instead of leaving it intact. The before-fix test reproduces the
wrong table; after the fix it also verifies result position, editor, selector and
visible error. This is a UI state-loss defect; database corruption was not shown.

`AppState::switch_browse_table` now validates the target and guards drafts/busy SQL,
loads a fresh target context, and restores the complete previous tab on query
failure. Selector polling and Apply propagate the error and rebuild from retained
state. The poll returns after switching so stale grid selection is not copied
into a different table. Source WHERE/global/column filters do not leak into an
unrelated target schema.

- Resolution: `8ab0778f3a16a915bc09116454912b6fd8a0992b`, Codex.
- Verification: baseline failure, 292 passing workspace tests and the inspected
  Soft failure capture. Native interaction acceptance remains separate.

## Keyboard and remaining scope

at both ends, and uses the guarded switch. Compared with the switchTable lambda
in official v3.13.1 TableBrowser.cpp. Existing focus/overlay/modifier guards remain.

for each table. This is an explicit shortcut in code and the next parity gap.
