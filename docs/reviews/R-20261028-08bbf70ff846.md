## Implementation and source comparison

[DB4S v3.13.1 EditTableDialog.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/EditTableDialog.cpp)
confirms deletion in existing tables and calls `removeKeyFromAllConstraints` in
[sqlitetypes.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqlitetypes.cpp).
The example now atomically updates key membership and per-row state, retaining
names/order/collation/conflicts and stable owners while users repair draft names.
Empty constraints disappear; composite foreign parent definitions remain intact
for review, with mismatched arity rejected by existing Save validation.

Tests exposed the old requirement to clear/save PK membership before deleting its
column. Complete key drafts now replace SQLite-owned indexes, while explicit indexes
remain protected. Retired columns temporarily retain unique names for native DROP
dependency validation after one rebuild, including removed-name reuse. Their plain
ANY storage avoids executing discarded generated/NOT NULL rules. The containing
savepoint preserves data, dependencies and pending edits on every failure.

A quoted dependent view can otherwise silently interpret a removed identifier as
text under SQLite's DQS compatibility behavior. Only native DROP runs with both DQS
modes disabled, then restores them before further operations; an initial broader
scope correctly failed TEMP rename tests and was narrowed. This follows the purpose
of SQLite's [DQS connection options](https://www.sqlite.org/c3ref/c_dbconfig_defensive.html)
and retains native [DROP dependency checking](https://www.sqlite.org/lang_altertable.html).

First visual captures exposed opaque scrims and white text on pale buttons. Shared
themes/defaults now use alpha and distinct action text tokens. `ModalStyle` gains
`secondary_fg` (local literals/callers updated). e28 defaults deletion to Cancel and
restores Modal focus after rebuilding. No dependency/config/platform source change.
