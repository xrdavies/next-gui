## Scope and upstream reference

Compared v3.13.1 [TableBrowser.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/TableBrowser.cpp),
`sortByColumn` and `clearSorting`. The prior three-state single-column cycle was
not the upstream behavior. Ordinary clicks now alternate ascending/descending on
one column, or replace a multi-column list. Ctrl/Command clicks append a priority
or toggle that column in place; Clear Sort clears all terms. Headings show direction
and priority. Sorting selects the first result cell in the clicked column and syncs
the cell editor. Draft/busy guards and query failures retain the prior tab state.

Both ordinary/view and rowid queries share ordered, quoted identifiers. Missing
columns are rejected instead of becoming SQLite double-quoted string constants;
leading/trailing spaces and literal arrows/quotes remain part of names. Complete
CSV/JSON browse exports retain every sort term and remain independent of paging.
Native project XML restores and writes all sort columns in order, and legacy JSON
primary fields remain readable alongside an optional additional-order list.

## Framework and macOS parity

PointerButton now carries current `Modifiers` on Linux, macOS and Windows. Host
touch synthesis preserves those modifiers per sample; the existing `synthesize`
API still defaults to no modifiers. Direct event constructors must add `modifiers`
and exhaustive patterns must bind it or use `..`. All in-repo consumers build.
OS event forwarding was inspected and feature-checked; real Ctrl/Command clicks
and Linux/Windows runtimes were not accepted by synthetic tests.
