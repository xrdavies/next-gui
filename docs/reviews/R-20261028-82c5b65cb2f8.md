## Implementation and reference comparison

[DB4S v3.13.1 EditTableDialog](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/EditTableDialog.cpp)
`populateFields` installs QComboBox widgets in every Type/Collation cell. Types
are editable for ordinary tables and constrained for strict tables; collation
choices come from the connection. Its [datatype lists](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqlitedb.cpp)
are now used in the same order, retaining existing/custom field values.

The shared table adds opt-in dropdown columns. Every visible row paints a control;
first click requests the existing single cell editor. Checkbox behavior and ordinary
selected-click editing remain intact, without allocating a widget per database row.
Ordinary types use Autocomplete with an explicit all-options dropdown, strict types
and collations use Select. Existing validation, cancellation and draft flows remain.

A small-window capture exposed an existing Select popup extending beyond the right
edge. Select now shares the already-tested Autocomplete viewport/visible-option
geometry; painting, pointer indexing and wheel selection use the same range.
Labels clip to the panel and keyboard selection stays visible. Select gains
`selected_fg`; themed/default styles and consumers compile. Tabs use normal text
on chrome backgrounds, fixing light selected-tab contrast.
