## Implementation and source comparison

[DB4S v3.13.1 alterTable](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqlitedb.cpp)
saves related views/indexes/triggers and attempts to restore them. The example now
moves valid dependent view chains and their ordinary/TEMP view triggers in the same
savepoint as the table, retaining unchanged wrappers for ordinary same-schema
callers. The cross-schema helper returns moved view names to update qualified UI
and project identities. Missing destinations or conflicting names roll back all
objects and data, including prior pending edits.

SQLite authorizer reads identify dependencies through nested/derived queries.
SQL AST traversal retargets only database-qualified references to the moved table
and views, including nested SELECTs, CTEs, window/function clauses and trigger DML
expressions/upserts. It preserves unqualified names, functions, aliases and string
literals. Other dependencies remain subject to actual destination compilation;
TEMP views/triggers may legitimately keep cross-database dependencies, following
SQLite's [view](https://www.sqlite.org/lang_createview.html) and
[trigger](https://www.sqlite.org/lang_createtrigger.html) semantics.

Moved view options are reconciled against actual output columns. Source field
renames follow direct view outputs while explicit aliases remain stable. Captured
mutation probes validate only actions that were valid on each original owner,
then validate them at the destination; no probe executes user data mutations.
