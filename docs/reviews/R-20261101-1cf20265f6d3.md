## Change and reference

File, Schema Options and both tree context menus offer source-checked Detach.
The shared tree hit API resolves the visible clicked row without changing
selection, expansion, focus or capture, excluding padding, scrollbars and
occlusion. Shift+F10 opens the corresponding context menu. Detach defaults to
Cancel, explains volatile attachments, rejects cell/external drafts, workers
and actual pending writes, and releases only clean read transaction locks.
Qualified Browse caches/settings, Schema sessions, conditional rules and
table Plot configurations reconcile; independent SQL/DDL drafts and SQL result
snapshots remain. Other aliases and database files are retained. Dependent
TEMP views report unavailable results instead of retaining stale rows.

Original v3.13.1 references: [MainWindow.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/MainWindow.cpp)
and [sqlitedb.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqlitedb.cpp).
SQLite's [DETACH documentation](https://sqlite.org/lang_detach.html) describes
independent aliases of the same file. Tests cover that behavior and verify
the database file bytes are unchanged. The example requires explicit Write
Changes/Revert before Detach, avoiding implicit transaction decisions.

### R-20261101-1cf20265f6d3-F02

**Detach retains removed-schema project metadata and can miss the Save prompt**

- Status: verified
- Severity: P1
- Owner: codex
- Platform: e28 / all
- Location: `detach.rs::detach_confirmed`, `project_xml.rs` native/extension metadata
- Introduced by: `1cf20265f6d3b9e5a2e510541635c3ea9a058e3b`

Two file-backed regression cases fail on the focus-fixed implementation:

```text
detach_empty_database_marks_a_saved_project_modified:
Detach must participate in Save Project/close confirmation

detach_project_roundtrip_removes_only_its_native_and_extension_settings:
removed native table settings must not survive Save Project
```

Removing an empty attached database changes no serialized Browse selection or
settings, and leaves `project_xml` unchanged, so `has_project_drafts()` is false.
For populated projects, Save rebuilds the live attachment list but retains native
per-table metadata for the removed schema. Plot/conditional-format restoration
can recover these obsolete entries, and restoring saved Browse settings may
query a schema that is no longer attached. The implementation must prune only
the removed schema from native attachment/tab/table metadata and synchronize its
cached extension without dropping other aliases or unknown project metadata.
Perform parse/validation before DETACH so malformed metadata cannot leave a
half-reconciled session. Verify XML and JSON save/reopen, unchanged database
files, other aliases, and remaining volatile attachments.

Evidence: `/tmp/next-gui-detach-project-before.log` (3 passed, 2 failed).
Full original parity F02 remains **in_progress**.
