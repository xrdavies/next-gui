## Scope and macOS parity

Upstream v3.13.1 `MainWindow::newTableBrowserTab` creates separate browser/model objects; `changeTableBrowserTab` changes the current browser without clearing its selection. e28 retains each tab's state while still requerying fresh results on activation. A selected rectangle is remapped by stable rowids only when every selected row still forms the same contiguous sequence. Missing/reordered records or changed column names clear the entire rectangle and editor. Views and WITHOUT ROWID tables require identical typed selected rows at the same cache positions, avoiding false identity from BLOB display labels. The original anchor direction, active cell, per-tab scroll and current value return; closing a tab restores the adjacent tab through the same helper.

New/close/switch operations reject SQL worker ownership before mutation. Their UI buttons leave focus order while disabled and become usable after completion. Existing draft/query-error rollback tests continue passing. No framework/dependency/on-disk format change was needed. The helper explicitly records that restoration is limited to the refreshed preview; whole-result/cross-page and discontiguous selection remain open.

The first application test omitted the rebuild that production `after_ui` performs after selection polling, then snapshotted stale editor widgets into a new selection and hit the existing draft guard. The test now follows the actual poll/rebuild/button sequence; this was a harness correction. No production stale-widget defect was inferred from it.
