## Behavior and remaining work

TextArea uses Unicode15 line opportunities to move fitting words as a unit,
falling back to complete grapheme clusters for long words. It retains source
scalars and existing fractional advances, bounds trailing whitespace and shares
one layout across painting, navigation, selection, pointer and IME/hint geometry.
Unwrapped mode and public character-layout methods retain existing behavior.
The checked cell tool now says Word wrap; preference/history/storage are retained.

The installed fontdue word layout rounds advances and uses different line metrics;
it cannot directly replace this shared geometry. Added pinned nodependency
`unicode-linebreak0.1.5` (Apache2, MSRV1.56, Unicode15); reused the existing
unicode-segmentation dependency. Registry checksum and Rust1.86 build verified.
See [upstream](https://github.com/axelf4/unicode-linebreak) and
[API](https://docs.rs/unicode-linebreak/0.1.5/unicode_linebreak/).

This establishes word boundaries, not complete shaping or Scintilla compatibility.
Scalar caret editing, bidi/RTL, missing emoji glyphs, discretionary hyphens,
non-LF mandatory separators and style-specific wrapping remain. Whole-document
layout remains O(document length); the earlier clipped raster budgets remain.
Stable `R-20261027-443ef848a739-F02` remains **in_progress** for full codecs,
dedicated binary editing/history/actions, shell/docking and remaining original
visual/product/native/platform parity. No completion/publication claim. Earlier
