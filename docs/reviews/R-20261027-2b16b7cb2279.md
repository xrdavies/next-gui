### R-20261027-2b16b7cb2279-F01

**Browse rejects a second statement only after preparing its PRAGMA side effects**

- Status: verified
- Severity: P1
- Owner: codex
- Platform: e28 / all
- Location: `db.rs::query_preview,export_table`
- Introduced by: pre-existing single-statement guard; discovered during subsequent SQL trace work

Follow-up runtime evidence: the new
`browse_rejects_tail_without_preparing_pragma_side_effects` regression fails before
the fix: filter `1; PRAGMA foreign_keys=ON; --` returns an error but changes the flag
from 0 to 1. `Batch::next` prepares the rejected tail; some PRAGMAs act during prepare.
SQLCipher key changes carry the same preparation risk. Full export previously
ignored the tail, giving different filter semantics from preview.

The fix prepares only the leading SELECT and compares its unexpanded-input-equivalent
expanded SQL with the complete generated query before stepping. Tail statements and
unbound parameters are rejected without preparing another statement. Preview and
export share this check. The regression now passes for both browse modes, PRAGMA
foreign_keys/key tails, valid semicolons in literals/comments, unchanged destination
exports and a successful unencrypted backup. e28 80 tests and strict clippy pass
in the working tree that also contains ongoing trace work.
