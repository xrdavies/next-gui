## Scope and macOS parity

Original v3.13.1 [MainWindow.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/MainWindow.cpp) saves/restores browse widths by header logical index and frozen prefixes by logical count. [TableBrowser.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/TableBrowser.cpp) applies those indices. [sqlitetablemodel.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqlitetablemodel.cpp) always puts a row-id/pseudo-key column before schema fields, including views and WITHOUT ROWID tables. Sort/filter indices instead refer directly to schema fields.

e28 converts widths by subtracting/adding one and frozen prefixes by saturating subtraction/addition, with visible-column bounds. It keeps original row-id width, attributes, visibility and a row-id-only frozen prefix while the row-id column remains unapplied. Visibility now appears in unapplied-settings notices. Per-tab extension widths/counts take precedence over shared native settings, retaining independent tab state and old e28 projects with the earlier incorrect native encoding. JSON and XML extension loads materialize old global counts before native conversion.

Old handmade native width fixtures were corrected to the original convention; validation/assertions were retained. The only failed intermediate tests were these old fixture indices, now corrected. A QA capture initially showed Structure; it was corrected to select Browse Data and re-run before saving the reviewed evidence. The final capture-only adjustment was targeted-test checked after the workspace run.

No shared framework/platform code changed. These conversions are common Rust paths. No new findings found. [Capture hashes](assets/R-20261027-caca01ed09f6/PROVENANCE.md).
