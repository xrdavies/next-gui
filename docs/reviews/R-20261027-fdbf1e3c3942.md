## Scope and public contracts

The existing ContextMenu/overlay implementation now supports a popup without a
layout host (`context_menu_popup`, `open_context_menu`), preserving underlying
focus. Menus consume keys ahead of underlying widgets; Escape and Tab close them.
Pointer hover is forwarded by e28. Context panels that fit the viewport clamp to
its edges; very tall menu scrolling remains absent. `has_open_popup` guards e28
record shortcuts while the header popup owns input.

`table_header_column_at` reuses the painting/sort geometry. The app first checks
`hit_widget` for occlusion. `set_table_active_cell` retains selection anchors and
rejects cells outside the rectangle, so selecting a column keeps the first active
cell without shrinking the full current-cache range during rebuild/polling.

`MenuStyle`/`ContextMenuStyle` add `hover_fg`, default white and theme `on_accent`.
External exhaustive literals need that field; workspace theme/default-based
constructors compile. New API behavior is shared with no macOS-specific branch.
An accessible name is assigned to the e28 popup; no OS accessibility bridge is
implemented. The browser now uses its accent fill with the existing selected
foreground, repairing light-theme selected-text contrast.

Original v3.13.1 `TableBrowser.cpp` header actions select the clicked column and
freeze through it. e28 now supplies those actions and Copy Column Name. Hiding,
show rowid, encoding, display formats and editable-view key actions remain.
Selection covers at most the current 500-row cache; the status gives the selected
record count. Whole-result column selection is still a parity gap. The clipboard
string/action path is tested in-process; actual OS clipboard delivery is not.
[Capture provenance](assets/R-20261027-fdbf1e3c3942/PROVENANCE.md) includes hashes.

### R-20261027-fdbf1e3c3942-F03

**Native DB4S viewport fields use a different column index convention**

- Status: open
- Severity: P2
- Owner: grok
- Platform: e28 project interchange
- Location: `project_xml.rs`, `restore_table_options` / `capture_connection`
- Introduced by: earlier native width mapping and recent freeze mapping.

Source inspection found that DB4S saves/loads `column_widths` by the Qt header
logical index and `freeze_columns` as a logical prefix count, including its
leading row-id column. e28 displays only schema columns and currently maps both
fields directly to that list. Sort/filter fields instead use schema field indices
and should not be shifted. Relevant upstream: `MainWindow.cpp` load/save browse
settings and `TableBrowser.cpp` header popup/viewport application.

Thus an original project for `(n,label)` with widths for logical columns 1 and 2
would put the width for `n` onto e28 `label`; a frozen prefix through `n` can freeze
an extra visible column. This is a source-based finding, not original-binary
acceptance. Existing handmade XML fixtures prove e28 self-roundtrip and validation,
not this original viewport convention. Earlier width/freeze reports should be
read with that limitation.

Next: add a native-convention regression, translate width/freeze fields separately
from sort/filter fields, preserve unapplied row-id metadata and legacy e28 state.
