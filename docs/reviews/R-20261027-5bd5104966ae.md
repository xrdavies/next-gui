## Scope and compatibility

Upstream v3.13.1 `TableBrowser.cpp` freezes through the clicked header column and
stores `frozenColumns` for the table. The e28 toolbar now freezes through the active
cell column (first column without a selection); a second click unfreezes. Counts
live with each tab's table options, and the shared Table/filter layout receives
the effective count. No framework primitive change was needed in this slice.
The original header context-menu gesture is still absent.

New projects save effective defaults as explicit tab/option overrides; old JSON
projects lacking the new field still use their legacy global count. New unseen
tables use the preference default. Counts are clamped to known result columns,
but a tab without results retains its saved count for checkpoint comparisons.
Native XML count syntax is validated. Explicit e28 tab overrides take precedence
over DB4S's shared per-table count; native projects without overrides use native
fields. Native DB4S cannot encode different counts for the same table in two tabs;
the existing e28 extension can. Full original-binary interoperability is unverified.

The previous report's missing-table wording is corrected: inactive missing-table
options are skipped; a missing selected table still fails project preflight.
[Capture provenance](assets/R-20261027-5bd5104966ae/PROVENANCE.md) records hashes.
