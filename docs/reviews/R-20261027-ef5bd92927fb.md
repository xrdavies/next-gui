## Scope and macOS parity

Shared Tabs now optionally use measured content widths and overflow arrows, consistent with the [Qt tab scroll-button reference](https://doc.qt.io/archives/qt-5.15/qtabbar.html#usesScrollButtons-prop). e28 enables this on its five dock titles. Ordinary equal-width mode remains the default for existing callers and DSL files. A new public `TabsStyle.scrollable` field requires exhaustive external struct literals to add that field or use defaults. The DSL `scrollable` property, theme constructor, exports, application rebuild, documentation and tests are updated together; no dependency or on-disk format changed.

Arrow clicks scroll the strip without switching panels. Keyboard selection automatically reveals its title, including re-selecting Home after manually scrolling away. An opaque `TabsState` restores manual scrolling only for identical titles/selection/mode, and matching width/font size. Longer-than-viewport titles can be scrolled between head and end; the selected accessible name remains complete. Arrows are part of the strip, not separately focusable; keyboard users reach the pages with existing navigation keys. No OS accessibility tree is claimed.

The first application test incorrectly tried to resolve auxiliary nodes through `widget_from_node`; auxiliaries are not registered widget owners, so both probe lists were empty. It was corrected to compare the public opaque viewport state, then exercise actual pointer dispatch and page polling. This was a test-harness correction, not a hidden production regression.
