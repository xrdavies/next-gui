## Implementation and macOS parity

The existing parser, anonymous validated snapshots and savepoint import policy
remain shared. Owned workers read native paths/Unicode clipboard and insert rows;
the UI polls finished handles and atomic byte/record counters. The live SQLite
connection transfers only after a worker successfully spawns, preserving it on
spawn/handoff failure. While insertion owns it, modal routing and database/document
actions block conflicting operations. Preview rebuilds avoid synchronous source
reads while a worker runs. Normal window close requests cancellation and keeps the
application open until work returns.

Cancellation checks both sides of each read and between SQLite rows. It never
calls SQLite interrupt, which can roll back the outer transaction. A running
record/read must return before cooperative cancellation completes; the Cancel
button disables and the caption explains the wait. The current file savepoint
rolls back, earlier completed files and pending edits remain. Genuine concurrent
SQLite errors and explicit trigger ROLLBACK are not swallowed. An unexpected worker
panic is surfaced; if insertion loses its connection, the database UI closes with
an explicit pending-rollback error. Existing snapshot memory/temp disk limits
remain. All old CSV callers and tests explicitly drive the new asynchronous flow.

Reference: [DB4S v3.13.1 CSV import](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/ImportCsvDialog.cpp).
No new dependency or shared framework API was needed.
