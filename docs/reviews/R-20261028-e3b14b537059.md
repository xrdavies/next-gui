## Implementation and safety

File menu exports now show all tables/views across main/temp/attached namespaces.
Single selection uses a save file, multiple selections an export folder. CSV
header/separator/quote/newline (including None/custom characters) and JSON pretty
print persist after success. Text/binary detection and base64 BLOBs follow the
[original export implementation](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/ExportDataDialog.cpp).
Full rows stream from SQLite; JSON keeps exact integer/null/finite numbers.

All destinations are preflighted against live DB/journal paths and filename
collisions, then all query results are staged before publishing. Each file is
atomic; a final filesystem publishing error can leave earlier files completed
and reports their count. No whole-directory atomicity is claimed. Export remains
synchronous (explicit shortcut); large files need cancellable worker progress.
SQL result export still uses its previous immutable snapshot path/options and
is the next implementation gap. No dependencies or configuration added.
