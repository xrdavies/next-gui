## macOS parity and implementation

The original [PlotDock mouseMove](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/PlotDock.cpp#L921)
converts pointer pixels into continuous axis coordinates, formats date/time X,
and omits categorical X. The shared opt-in `ChartStyle::show_plot_coordinates`
implements that interaction and adds named dual-Y values. It is off by default
in both themes and has validated DSL support. Full caption help remains available.
Exhaustive Rust ChartStyle literals need the new field or a default update.

A cached frame now retains the exact viewport used for its image. Hover converts
through the image's actual integer dimensions without rebuilding bar indexes or
scanning point buffers. Zoom, pan, resize and model mutation regenerate the frame
when required. The public image-export API and pixels remain unchanged.

Passive tooltip nodes no longer intercept widget hits. The existing wrapped
painter follows the pointer, flips/clamps to the window and clips long labels.
Window leave clears the passive tip without disturbing completion/menu selection;
e28 forwards that event. Both movement APIs support position updates, including
active Plot drags. Menus and caret hints retain their existing priority.

Initial compilation found the shared TextArea hint initializer needed the new
internal metadata default; it was fixed. The first app-menu assertion ran before
sync and was corrected to follow the host event sequence. The first native fixture
lost prepared hover during startup; setup now occurs after layout. Only corrected
captures are counted. Final public-feature workspace checks plus fresh strict/app/
build/native checks cover the last fixture-only change.
