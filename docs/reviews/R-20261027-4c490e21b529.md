This change supplies shared image fit/1:1/zoom/pan and reliable nested overflow
scrolling, then uses those controls in e28. It also repairs cell storage types,
foreign-key navigation, PRAGMA read-back, per-tab SQL results, CSV browse reset,
numeric chart input and project/preferences state. Draft protection is improved,
but the complete DB4S workflow and interface are still unfinished.

Expected load: one local database user, one active query worker and a static
PNG/JPEG preview within the existing 16-megapixel / 128 MiB decoder limits.

## Scope and implementation

Read the shared Image and ScrollArea layout/paint/hit/drag/wheel paths and their
e26/e28 callers, SQL worker/result/export ownership, database replacement and exit,
typed cell edits, foreign keys, PRAGMAs, CSV, chart data, projects and preferences.
The user's request explicitly authorizes framework and example product changes.
The initial eleven unpublished commits were preserved; no pull/rebase/reset or
main merge was performed. Remote refs were inspected read-only and still pointed
to the recorded ancestors before this work.

- `5938b86`: `ImageView` retains validated scale and bounded pan; fit/1:1 do not
  alter source pixels. Image drag/wheel use the shared input path. `scroll_row`
  wraps existing ScrollArea/Row controls, nested wheel dispatch follows actual
  scene ancestry and bubbles at limits, and overflow extents account for expanded
  child bounds. ScrollArea offset restoration is public and rejects non-finite
  input. Existing builders remain compatible.
- `4c490e21b529`: each SQL tab keeps its results, message, grid widths/viewport and
  export snapshot. Save as VIEW uses the executed read-only statement and an
  editable name, even after the editor changes. Open SQL creates a new tab.
- The cell dock uses the shared multiline editor and an explicit storage-type
  selector. Invalid Hex/JSON or numeric input preserves the draft; NULL and empty
  TEXT are distinct. Unchanged binary text previews retain original bytes. Cell
  navigation requires Apply/Discard; ordinary typing does not trigger a rebuild.
  SQLite column affinity still controls the final stored type.
- Foreign keys retain id/sequence, resolve implicit parent primary-key columns,
  and navigate all composite components using stored typed values and the
  existing safe SQL literal encoder. NULL has no parent; missing usable rowid
  remains an explicit limitation.
- PRAGMA updates validate input and compare read-back values using setting-specific
  normalization. A mismatch reports the actual value and partial application;
  auto_vacuum transitions requiring VACUUM do not claim success or rebuild the
  database automatically. Numeric chart samples exclude invalid/non-finite values
  and errors surface instead of becoming empty charts. CSV resets old browse state.
- Projects retain table-scoped conditional rules, plot source, read-only mode and
  DDL with optional serde defaults for older JSON. A saved checkpoint detects
  SQL/project/cell/PRAGMA drafts. Preferences Cancel preserves active frozen columns.
  This remains the example's JSON format, not upstream DB4S XML compatibility.
- The shell/pages/docks and long action/tab/filter strips scroll and restore
  offsets. Image controls include Fit, 1:1, zoom, pan and original-byte export;
  export destinations use the database/journal overwrite guards. No new dependency,
  platform backend or database format was added.

## Handoff and remaining limits

- F02: replacing a project with unsaved drafts is refused, and Exit offers
  discard/cancel. A unified Save/Discard/Cancel transition covering every document
  type, destination and New/Open/Close/Exit action is still missing. No autosave or
  crash recovery is claimed.
- F10: scrolling makes previously unreachable controls accessible, but the shell
  still has a 1100px logical workspace. Adaptive pane layout, splitter-ratio
  persistence, visible scrollbars and alignment of filter controls with resized/
  horizontally scrolled/frozen table columns remain unfinished.
- F13: application memory retains the last 200 whole manually executed batches;
  the dock still previews up to 100 shortened entries. Full SQLite engine tracing,
  category/result filters, clear/export and an explicit eviction indicator remain.
  No new trace hook logs SQLCipher keys or other sensitive connection setup.
- Broader parity remains in PARITY.md: DB4S XML projects, movable/closable tabs and
  docking, advanced Table/code/Hex editing, attached-schema browsing, arbitrary
  table-rebuild migrations and richer plots/dialogs. This iteration adds no
  speculative abstraction for those features.
- Preview uses nearest-neighbor scaling and original encoded-image export, not
  general image editing. Result snapshots still use private plaintext temporary
  files and disk space as documented in the previous implementation.

Next acceptance step: a visible native desktop run covering pointer/keyboard,
