## Scope and macOS parity

The platform already maps desktop PageUp/PageDown and e28 already maps Shift variants. Shared `key_text_area` now handles them without app-specific paging. A page is the fully visible visual row count minus one (minimum one); caret and bounded viewport move together. Shift retains its initial anchor. Wrapped lines use the current text layout. Read-only documents stay unchanged and the opaque session carries the resulting selection/viewport across rebuild.

Keyboard row targeting now uses nearest actual layout row, while pointer targeting retains floor-to-pointed-row behavior. This avoids floating-point floor errors at fractional font heights for Up/Down, pages and Home/End. No paint/style/persistence/API shape changed. The final comment-only addition records the remaining desired-column limitation.

Original DB4S uses QScintilla. The [Scintilla keyboard contract](https://www.scintilla.org/ScintillaDoc.html#KeyboardCommands) includes page commands and extending variants; current documentation is reference behavior, not acceptance of the exact DB4S binary. [Capture provenance](assets/R-20261027-4bb6e7d46905/PROVENANCE.md).

### R-20261027-4bb6e7d46905-F03

**Vertical movement forgets the desired horizontal column after a short line**

- Status: verified
- Severity: P2
- Owner: grok
- Platform: shared UI / e28
- Location: `TextAreaEdit`, `key_text_area`
- Introduced by: pre-existing current-x navigation, inherited by page movement.

Source-based finding: every vertical key takes x from the current caret and no editing state remembers a desired x. After landing on a short line, another vertical move targets that shorter x instead of the prior column. [Scintilla](https://www.scintilla.org/ScintillaDoc.html#SCI_CHOOSECARETX) retains the explicitly chosen horizontal position. Add a long/short/long regression, retain a desired x through vertical moves and rebuild, and reset it for explicit placement/edits/horizontal moves. Originally recorded by a `shortcut:` comment. Runtime baseline subsequently reproduced caret 14 vs 21. Resolution/verification at `4356e82aef7bf3da0edd41419bca10b600a980f0`: desired x retained across short lines/Shift/rebuild; explicit placements, edits and changed width/font reset it. The limitation comment is removed. All 322 workspace tests and strict checks pass. See [verification](R-20261027-4356e82aef7b.md).
