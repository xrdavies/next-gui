## Scope and macOS parity

Shared `set_text_area_foregrounds` accepts disjoint Unicode scalar ranges and colors, validates atomically, and preserves the document, selected content and Undo history. Same-document sessions carry colors; actual edits/Undo/Redo clear stale offsets. Preedit uses normal text while composition offsets differ. Selected glyphs use the normal foreground so syntax colors do not reduce selection readability. Color masks include visible glyphs only; gutter, search marks, plain glyphs, colored glyphs and caret retain their intended order as nodes are reused. No public style literal, dependency or file-format change.

The app adds lexical token colors to the SQL/Find editor and refreshes them after input or session/theme restoration. Keyword recognition uses the linked engine's [keyword-check API](https://sqlite.org/c3ref/keyword_check.html). The lexer covers quoted strings/identifiers, doubled quotes, BLOBs, decimal/exponent/hex numbers and underscore separators, plus positional/named/Tcl-style parameters following the [SQLite expression reference](https://sqlite.org/lang_expr.html). [Comments](https://sqlite.org/lang_comment.html) terminate at LF/end or the first closing block marker and do not nest; CR-only line comments remain comments through end-of-input. Tests cover unfinished tokens without turning their inner words into keywords.

This is lexical presentation, not semantic SQL validation or a schema-aware parser. Function coloring recognizes a name followed by whitespace and an opening parenthesis. Retokenization is synchronous, explicitly recorded as a shortcut for large scripts. Semantic completion, style preferences, folding/bookmarks and the complete original editor remain open. No remaining new product findings were found in this slice; current visual acceptance remains incomplete as recorded above.
