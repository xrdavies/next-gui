## macOS parity and implementation

Original [MainWindow.cpp](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/MainWindow.cpp#L1074)
loads the selected result into Edit Cell, restricts writes to an editable Browse
model and clears invalid SQL selection. The example now reads a SQL cell from the
existing complete typed snapshot, including rows outside the500-row Plot preview.
The active range endpoint selects the cell. No SQL is rerun and no point/result
payload is recopied for unchanged selection.

An explicit Browse/empty-SQL/selected-SQL source distinguishes editor ownership.
Snapshot identity and coordinates suppress repeated loads and preserve current
view mode across rebuilds. Errors clear stale contents and cache their source to
avoid repeated failing rebuilds. Query/tab changes and reopen refresh the visible
selection; returning to Browse restores that model's selected value. Empty SQL
selection clears the viewer. Existing Browse drafts block replacement.

SQL storage labels and values are read-only. Backend Apply also rejects SQL
sources, so changing a label or invoking an action directly cannot write a query
cell into an unrelated Browse record. Copy and Text/Hex/JSON/image views remain
available. Invalid UTF-8 TEXT keeps raw bytes in Hex with its TEXT storage tag;
it cannot enter the writable TEXT conversion path. Common load/clear helpers reset
byte/image metadata, and database close clears the source.

The toolbar regression was adjusted to assert the original empty-SQL clear and
Browse-return behavior rather than keeping an old Browse value on an empty query
page. The first renderer test displayed the default query while executing a
supplied UPDATE string; the final fixture now displays and executes the same SQL.
Only the final matching captures are included.
