## Scope and data safety

Load All captures Browse using the existing connection, namespace, composed filter and
ordering. SQL uses its already executed immutable typed result file; UPDATE RETURNING
is never replayed. Files are indexed without duplicating cell payloads and streamed
sequentially for plotting. Only a completed successful model replaces the previous
plot. Cancellation restores the previous settings/buffers and returns the connection
without committing pending database changes. Connection handoff reuses the existing
spawn-before-transfer export worker, now generic over the result type.

Browse validates the visible page against the full snapshot and checks every attached
schema's [SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)
on the same connection. Matching page changes retain full plot navigation/buffers;
external writes or explicit refresh invalidate them. Own commits invalidate explicitly,
because data_version does not change for a connection's own commit. Point selection
outside the current Browse page reveals that page without re-querying the full plot.

The [original PlotDock](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/PlotDock.cpp)
provides the full-cache behavior reference. The million-row test exercises the complete
backend snapshot/cache/cancel/style/invalidation workflow in11.39s in debug mode;
this is neither a benchmark nor native responsiveness acceptance.
