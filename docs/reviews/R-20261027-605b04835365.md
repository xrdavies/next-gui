## Scope and reference

Shared `show_text_area_completions` accepts app-filtered labels and insertion text, anchors a bounded menu to the focused TextArea caret, and replaces the supplied Unicode scalar range. It reuses themed menu painting and validates the document, unselected caret, focus, read-only and IME state before accepting. Completion overlays are transient across rebuilds; editing sessions retain the accepted edit and Undo. The API adds no dependency or public style field. OS screen-reader active-candidate semantics remain unavailable.

e28 provides three-character automatic suggestions and Ctrl/Command+Space explicit suggestions in SQL and Find editors. Metadata is cached on schema/extension refresh, so suggestions never borrow a worker-owned connection or execute editor SQL. A malformed view can omit its columns while other candidates remain available; an explicit request surfaces the metadata warning in the status bar. Built-in functions remain available after closing a database, while old object/custom-function names are discarded.

The reference [SqlTextEdit](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/sqltextedit.cpp) configures API completion at three characters. [SqlUiLexer](https://github.com/sqlitebrowser/sqlitebrowser/blob/v3.13.1/src/SqlUiLexer.cpp) supplies keywords/functions and schema.table/table.column/isolated-column paths. Its provider is a static API catalog; query-scope alias/CTE analysis is an additional IDE capability, not an established requirement from this provider. e28's runtime catalog follows the linked engine's [keyword API](https://sqlite.org/c3ref/keyword_check.html) and read-only [function_list/table_xinfo metadata](https://www.sqlite.org/pragma.html#pragma_function_list). Function argument descriptions/calltips, original keyword output-case preferences, folding/bookmarks, full styling and editor navigation remain unfinished. Lexical/catalog scans are synchronous, with a recorded profiling upgrade point for large documents/schemas.
