## Framework gap and resulting behavior

The previous virtual_table reduced scene nodes but still required an in-memory Vec
of every row, and painting cloned that Vec. The new immutable TableDataSource and
data_table fetch only visible rows with overscan; global row counts drive scrolling,
selection and copying. Existing eager APIs keep their behavior, with shared immutable
row buffers for cheap painting clones. Read failures paint an inline error and are
available through take_table_data_error; failed copies return no partial text.

SQL records byte offsets while writing its existing private typed result file. The
SQL grid uses that indexed snapshot automatically, while the Plot retains an optional
500-row preview until Load All. Plot full loads reuse the same index. RETURNING and
UDF-bearing queries are never replayed for scrolling, copy or plotting. SQL tab state
now retains selection anchors/endpoints along with its existing widths and viewport.
Full Plot point/range selection reveals the corresponding global SQL rows.

## Stable finding and practical limits

`R-20261027-443ef848a739-F02` remains **in_progress**. This removes the500-row SQL

The index uses memory proportional to row count; cell payloads stay on temporary
disk, with only visible rows decoded for painting. Row reads are synchronous local
I/O, so one exceptionally large row can still delay a frame. Copies allocate their
selected text and decoded row, consistent with existing clipboard behavior. Snapshot
files remain private plaintext until their last result/tab/plot reference closes.
