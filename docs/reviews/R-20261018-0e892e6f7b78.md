## Findings

### R-20261018-0e892e6f7b78-F01

**`request_exit` waits for an unrelated keyboard event outside key callbacks**

- Status: fixed
- Severity: P2
- Owner: grok
- Platform: shared Linux/macOS backends; reproduced on macOS; Linux re-verified
- Location: `crates/next-gui-platform/src/macos.rs`, `linux.rs`; public contract `lib.rs` `request_exit`
- Introduced by: `33700c4d0fe5575ec487e5a330be54417813223e`

#### Finding

`WindowCtx::request_exit` promises to leave the event loop after the current callback.
The flag is checked only inside `WindowEvent::KeyboardInput`. Calling it from
`on_start`, `on_redraw` or a pointer callback leaves the window running indefinitely
until a recognized key is delivered. A mouse-driven Quit button therefore does not quit.

#### Evidence

A temporary consumer linked against the reviewed platform crate requested exit in
each of those three callbacks. A small window presented a flat frame; the pointer
case received an actual click. Each process was observed for 1.2 seconds after the
request, then sent an unrelated Space:

```text
request site      alive after callback   exit after unrelated Space
on_start         true                   0
on_redraw        true                   0
PointerButton    true                   0
```

The minimal startup case can be reproduced with the existing platform dependency:

```rust
use next_gui_platform::{run, AppCallbacks, Event, WindowAttrs, WindowCtx};

struct QuitOnStart;
impl AppCallbacks for QuitOnStart {
    fn on_start(&mut self, ctx: &mut WindowCtx<'_>) { ctx.request_exit(); }
    fn on_event(&mut self, _: &mut WindowCtx<'_>, _: Event) {}
    fn on_redraw(&mut self, ctx: &mut WindowCtx<'_>) {
        let (w, h) = ctx.size();
        ctx.present(w, h, &vec![0x303030; (w * h) as usize]).unwrap();
    }
}

fn main() {
    run(WindowAttrs::new("quit probe", 320, 120), QuitOnStart).unwrap();
}
```

Source inspection confirms Linux has the same single flag check. That is a code-based
portability conclusion, not a Linux runtime result.

#### Impact

Clients using the new common API for a Quit button or lifecycle shutdown cannot rely
on it. Escape demos happen to work because they request exit in keyboard callbacks.

#### Recommendation

Observe the pending exit after every supported callback path on both backends,
including early returns. Add a bounded regression for startup and pointer-requested
exit that completes without injecting a keyboard event.
