## Implementation and limits

Original MainWindow load/save fields and sqlitedb::setPragma behavior were read
from v3.13.1. A shared catalog now drives labels, controls and validation. Boolean
switches/enum choices preserve aliases and secure_delete FAST; numeric text inputs
validate SQLite limits and reject SQL tails. case_sensitive_like has no readable
PRAGMA result, so its current LIKE behavior is inferred with an expression;
unchanged user-defined LIKE functions are retained and tooltip explains the inference.

Dirty edits require explicit Save and Apply, default Cancel. All changed values
validate before committing; page_size/auto_vacuum trigger VACUUM and cached row
identities are invalidated. Every write reads actual state and partial errors
remain visible; a new deferred edit transaction is restored on success/failure.
No-op does not commit. Original numeric spinbox +/- affordances remain absent;
VACUUM is synchronous and can block on large databases. Text wrapping in the shared
confirmation breaks words and label alignment still needs polish. These are open
work, not evidence of full interface acceptance.
