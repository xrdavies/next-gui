## Review scope

`BrowseTableOptions` holds metadata only: WHERE/global/column filters, ordered
sort terms and column widths. Each browse tab keeps an independent map keyed by
table name. Leaving a table records its current options; returning applies them
before querying. Selection, cached result rows and rowids are not stored in the
map. A failed query/invalid width retains the previous tab and editor.

The new field defaults to an empty map for old JSON projects. The existing e28
XML extension also retains it. Native DB4S capture now writes inactive as well
as active supported table settings; active state wins over older saved entries.
The existing XML parsing/validation is shared for selected and inactive tables.
Existing sort attributes and unrelated inactive freeze metadata remain intact.
Raw SQL WHERE is an e28 field retained by JSON/the extension, not a new native
DB4S field. Inactive saved options for missing tables are skipped rather than queried or rewritten.
A missing selected table still fails project preflight.

Project preflight now validates saved inactive table queries and widths before
connection replacement. Selected table widths are checked too. A table-less tab
still validates its saved settings. This extends the earlier project preflight
and guarded-switch work; [8ab0778 F01](R-20261027-8ab0778f3a16.md#r-20261027-8ab0778f3a16-f01)
remains verified by the regression suite. No new unresolved defect was found in
this slice. [Capture provenance](assets/R-20261027-db7f25222647/PROVENANCE.md) records hashes.
